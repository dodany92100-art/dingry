ARCHITECTURE CATALOGUE (RÉSUMÉ FACTUEL)
-------------------------------------
1) Vitrine fallback : lib/shop-data.ts (PRODUCTS) — URLs Cloudinary en dur dans le code.
2) CRM : Supabase (+ snapshot store) — lib/admin/store.ts
3) API publique : app/api/catalog/route.ts → getCachedCatalogProductRows
4) Fusion vitrine : lib/catalog/index.ts → overlayShopCatalog(fallback, live, removedCatalogIds)
5) Seuls produits publishStatus !== "draft" exposés : lib/admin/types.ts → toCatalogProduct()
6) Client boutique : components/organisms/shop/hooks/use-shop-catalog.ts fetch /api/catalog
7) Images uploadées admin : R2 (lib/r2/storage.ts) ou legacy Vercel Blob ; delete via deleteProductImage dans store.ts
8) removeProduct : supprime fiche Supabase + médias ; seed IDs → removedCatalogIds (tombstones)
9) NE PAS utiliser npm run purge:r2 en prod si des produits live pointent encore vers R2.
10) Scripts utiles : check:prod-env, migrate:r2-images, import:supabase — package.json scripts
